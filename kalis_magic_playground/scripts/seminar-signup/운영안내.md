# 칼리의 대번개 신청 명단 운영 안내

대번개는 2026년 12월 15일 오전 10시(한국 시간)부터 최대 60명을 접수합니다. 현재 사이트의 신청 버튼은 닫혀 있습니다. 카카오뱅크 계좌번호·예금주·문의처와 테스트 시트 검증을 마친 뒤 개시하세요.

## Google 계정에서 준비하는 다섯 단계

1. Drive에서 기존 대번개 스프레드시트를 여세요. 공유의 일반 액세스는 ‘제한됨’으로 두고 웹 게시를 끕니다. 행사 신청과 문의는 이 파일 안의 탭으로 구분합니다.
2. 시트의 ‘확장 프로그램 → Apps Script’에서 기존 프로젝트를 열고 이 폴더의 `Code.gs`를 붙여넣고 저장하세요. 이 명단에 기록하는 Apps Script 프로젝트는 하나만 둡니다.
3. 프로젝트 설정의 스크립트 속성에 아래의 양식별 속성을 입력하세요. 시트 ID는 파일 주소에서 확인하고 허용할 행사 목록은 아래 컵앤볼 준비 절차에 따라 설정합니다. 서명 키는 비밀 관리 경로에서 받고, Netlify Functions와 같은 키를 넣습니다. 시험 환경에는 별도 파일·프로젝트·배포·키를 씁니다.
4. 편집기에서 아래 컵앤볼 준비 절차에 따라 두 탭을 순서대로 설정하고 필요한 시트 접근을 승인하세요. 대번개 원본에 신청 행이 있거나 제목이 예상과 다르면 대번개 설정이 중단됩니다. 이 경우 명단을 보존하고 담당자에게 확인하세요.
5. ‘배포 → 배포 관리’에서 기존 웹 앱을 선택하고 ‘수정 → 새 버전 → 배포’로 업데이트하세요. 실행 사용자를 ‘나’, 액세스를 ‘모든 사용자’로 확인합니다. 기존 주소를 계속 사용합니다. 끝이 `/exec`인 배포 주소를 비밀 관리 경로로 사이트 담당자에게 전달하세요. 시트 자체의 공유는 ‘제한됨’으로 유지합니다. 조직 정책이 익명 웹 앱을 금지하면 접수를 닫아 둡니다. [Google 웹 앱 배포 안내](https://developers.google.com/apps-script/guides/web)

## 촬영·개인정보 안내를 개정할 때

안내 문구를 바꾸면 담당자가 해당 안내의 버전도 올립니다. 서버의 `photoConsentVersion`은 Apps Script의 `SEMINAR_PHOTO_CONSENT_VERSION`과, `consentVersion`은 `SEMINAR_CONSENT_VERSION`과 맞춥니다. 기존 명단의 버전과 확인 시각은 그대로 보존하세요. 고지 개정에는 시트 준비 함수를 다시 실행할 필요가 없습니다.

## 입금 확인과 삭제

시트에서 필터 보기로 ‘입금’ 열의 0을 선택합니다. 거래 내역의 입금자명과 금액이 모두 일치하면 맨 오른쪽 ‘입금’을 0(미입금)에서 1(입금 확인)로 바꾸세요. 새 행은 0이고, 1이면 행 전체가 초록색으로 표시됩니다. 이름이 겹치거나 금액이 다르면 해당 연락처로 확인합니다. 입금 기한은 원래 접수 시각에서 24시간 뒤입니다. 미입금 행도 60석에 포함합니다. 행 삽입·삭제·부분 정렬은 피하세요.

CSV가 필요하면 ‘신청 명단’ 탭을 열고 파일 메뉴에서 현재 시트를 CSV로 내려받습니다. CSV를 다시 가져올 때 텍스트를 숫자·날짜·수식으로 자동 변환하는 옵션을 끄고 전화번호 첫 0과 이름의 첫 문자를 확인하세요. 내려받은 사본도 삭제 대상에 포함합니다.

2027년 2월 9일에는 접수를 닫고 대번개의 ‘신청 명단’ 탭 또는 그 탭의 신청 행을 삭제하세요. 내려받은 CSV, 별도 사본, 테스트 명단과 스크립트 속성의 해당 행사의 임시 제한 카운터도 정리합니다. 관리형 계정의 보존 정책이 있다면 개시 전에 고지한 기간과 일치하는지 확인하세요.

## 격리 테스트 모드

숫자가 모두 0인 계좌는 일반 설정에서 공개 견적과 직접 신청 POST 모두 차단합니다. 시험용 제로 계좌를 쓰려면 서버에서 `SEMINAR_TEST_MODE=true`를 명시하고, `SEMINAR_TEST_SHEETS_WEBAPP_URL`에 사전 확인한 별도 시험 웹 앱 주소를 지정해야 합니다. 실제 저장 주소인 `SEMINAR_SHEETS_WEBAPP_URL`과 정확히 일치해야 하며 시험 파일·키는 운영과 분리합니다. 브라우저 입력으로 테스트 모드를 켤 수 없습니다.

테스트 모드는 로컬 또는 Netlify의 `deploy-preview`·`branch-deploy`에서만 사용합니다. `CONTEXT=production`이면 설정이 있어도 접수를 차단합니다. Netlify에서는 배포 문맥이 `deploy-preview` 또는 `branch-deploy`여야 하며, 이 두 문맥은 `NODE_ENV=production`으로 빌드해도 테스트 모드를 허용합니다. Netlify의 배포 문맥이 없거나 다른 값이면 차단합니다. Netlify 밖의 로컬 실행에서는 `NODE_ENV=production`일 때 테스트 모드를 차단합니다. 테스트 영수증에는 `test=true`와 `payment.test=true`가 포함되어 ‘테스트 접수 · 송금하지 마세요’를 표시합니다. 운영 개시 전 두 테스트 설정을 제거하고 실제 계좌로 다시 검증하세요.

시험 환경 전용 설정 이름입니다.

```text
SEMINAR_TEST_MODE
SEMINAR_TEST_SHEETS_WEBAPP_URL
```

## 테스트 배포 인수

시험용 시트의 공유와 배포 ID를 담당자끼리 확인하고, 시험용 키와 가짜 계좌만 연결하세요. Google 로그아웃 브라우저로 가짜 신청 1건을 제출한 뒤 시트 링크 접근 차단, 시트의 한 행과 영수증의 합계·기한 일치, 입금 값을 1로 바꿨을 때의 초록색 행을 확인합니다. 59행 시험 사본에서는 두 요청을 동시에 보내 성공 한 건·매진 한 건·최종 60행을 확인하고, 성공 건을 같은 키로 다시 보내 접수번호와 기한이 같은지 확인합니다. 시험 CSV는 스프레드시트에서 다시 열어 텍스트를 확인하고 시험 파일과 내려받은 사본으로 삭제 절차까지 연습합니다.

개시 전 사이트 담당자는 허가받은 배포 주소와 서명 키를 사용하는 서버 환경에서 `node scripts/seminar-signup/check-ready.mjs`를 실행합니다. 명단 접근과 제목 행 확인에 성공하고 시험 배포 인수가 끝나면 운영 스위치와 안내 버튼을 순서대로 엽니다. 확인 결과에는 개인정보와 비밀값이 출력되지 않습니다.

## 컵앤볼 전용 준비 (2026-11-27)

이번 구현의 컵앤볼 신청 주소는 `/seminar-signup/cupsnballs.html`입니다. 주소 상수는 `seminar-signup/event-config.mjs`의 `CUPSNBALLS_FORM_URL`입니다. 소개 페이지의 신청 버튼도 이 주소로 연결됩니다. 접수는 한국 시간 2026년 11월 27일 18:00부터 12월 19일 00:00 전까지이며, 12월 7일과 14일 00:00에 각각 60,000원, 70,000원으로 바뀝니다. 첫 구간은 50,000원입니다. 공개 정원·잔여석과 15명 자동 마감은 없으며, 입금 기한은 접수 후 24시간입니다.

신규로 공용 파일을 준비한다면 기존 대번개 파일 ID를 `SEMINAR_SHEET_ID`와 `CUPSNBALLS_SHEET_ID`에 똑같이 입력하고 `SEMINAR_EVENT_ID=daebeongae,cupsnballs`로 설정하세요. 먼저 `setupCupsnballsSheet()`를 실행해 ‘컵앤볼 신청 명단’ 탭을 만듭니다. 컵앤볼은 A열 ‘접수번호’에 내부 UUID, AE열 ‘표시 접수번호’에 14자리 번호, AF열 ‘신청 구분’, AG열 ‘사이트 회원 식별자’, AH열 ‘입금’을 두는 34열 구성입니다. 초기 구성에 한해 제목만 있는 대번개 ‘신청 명단’ 탭을 21열에서 31열로 갱신할 때는 `setupDaebeongaeSheet()`를 실행하세요. 대번개의 마지막 AE열은 ‘입금’입니다. 빈 ‘시트1’은 그대로 두세요. 문의는 같은 파일에서 `setupInquirySheet()`로 준비합니다.

### 기존 컵앤볼 명단의 표시 접수번호 전환

1. 컵앤볼 신규 접수를 닫고 ‘컵앤볼 신청 명단’ 탭과 필터 설정을 백업하세요. 기존 제목이 A-AE 31열이고 마지막 AE열이 ‘입금’이며 신청 행은 0개여야 합니다. `79eb758`의 준비 함수는 기본으로 열별 조건이 없는 A-AE 필터를 만들며, 마지막 신청 행을 삭제한 뒤 정확한 제목만 남은 명단도 전환할 수 있습니다. 먼저 격리 시험 사본에서 아래 순서를 확인하세요.
2. 해당 Apps Script 프로젝트에 새 `Code.gs`를 저장한 뒤 편집기 함수 목록에서 인수 없이 `migrateCupsnballsSheet`를 실행하세요. 예전 31열 제목이 정확히 일치하는 빈 명단을 잠금 안에서 전환합니다. 이미 새 32열 제목이면 그대로 종료합니다. `existing_rows_preserved` 또는 `existing_header_preserved`로 거절되면 기존 데이터를 보존하고 운영 담당자와 전환 방식을 정하세요.
3. 기존 A열이 ‘접수번호’로 남아 있고 AE열이 일반 텍스트 형식의 ‘표시 접수번호’, AF열이 ‘입금’인지 확인하세요. AF에서만 숫자 0과 1이 허용되는지, 1일 때 행 전체가 초록색으로 표시되는지, 보호 범위에서 AF의 데이터 행만 수정할 수 있는지 시험하세요. 필터가 AF까지 포함되고 기존 조건이 유지됐는지 백업과 대조하세요. 기존 입금 필터와 맞춤 수식 안에서 이 탭의 AE만 가리키는 참조는 AF로 옮깁니다. C열의 `=LEN($C2)>0`처럼 영향을 받지 않는 조건은 그대로 유지합니다. 컵앤볼 명단 전환에는 대번개와 문의의 준비 함수를 호출할 필요가 없습니다.
4. 담당자가 기존 웹 앱 배포를 새 버전으로 갱신한 뒤 `node scripts/seminar-signup/check-ready.mjs cupsnballs`와 `node scripts/seminar-signup/check-ready.mjs daebeongae`를 실행하세요. 격리 시험에서 새 신청의 AE 값과 완료증·복사 문구가 일치하고, 같은 신청을 재전송하면 같은 번호가 나오는지 확인한 다음 신규 접수를 다시 엽니다.

표시 접수번호는 접수 시각의 한국 시간 12자리와 01-99 순번을 이어 만든 14자리입니다. 같은 분에 99개 번호를 소진하면 다음 분에 다시 신청할 수 있습니다. 삭제되거나 저장에 실패한 번호는 다시 사용하지 않습니다. 접수 기간에는 스크립트 속성의 `seminar_receipt_cupsnballs_`로 시작하는 발급 카운터를 보존하세요. 예전 영수증에 표시 접수번호가 없으면 기존 UUID가 표시됩니다.

`unsupported_filter_layout`, `unsupported_filter_formula` 또는 `payment_filter_conflict`가 나오면 전환 전에 중단되어 명단과 필터가 그대로 유지됩니다. 이 탭의 AE와 다른 열을 한 범위로 묶는 수식, 기존 AF를 참조하는 수식, 이름이 지정된 범위, 대상 셀이 확정되지 않는 `INDIRECT` 수식 등은 자동 전환을 중단합니다. 기존 필터를 백업한 상태에서 범위·맞춤 수식·중복된 입금 조건을 운영 담당자와 확인한 뒤 컵앤볼 탭에서만 정리하고 함수를 다시 실행하세요. 시트에 정의한 함수를 필터에서 호출한다면 함수 내부의 입금 열 참조도 직접 확인하세요. 실행 중 오류가 나면 필터를 백업과 대조하고 입금 조건이 현재 입금 열을 가리키는지 확인하세요.

서버의 컵앤볼 전용 환경변수 이름은 다음과 같습니다. 실제 값은 저장소·문서·캡처에 적지 않습니다. `SEMINAR_BANK_ACCOUNT`, `SEMINAR_BANK_HOLDER`는 대번개와 공유하는 카카오뱅크 그룹입니다. 각 양식의 연결 속성을 명시적으로 설정하세요.

```text
CUPSNBALLS_SIGNUPS_ENABLED
CUPSNBALLS_SHEETS_WEBAPP_URL
CUPSNBALLS_SHEETS_SIGNING_SECRET
CUPSNBALLS_HMAC_SECRET
CUPSNBALLS_TEST_SHEETS_WEBAPP_URL
```

시험 웹 앱·파일·키를 운영과 분리하고 격리 테스트 모드 조건을 동일하게 적용합니다. 연결 검사는 담당자가 허가받은 서버 환경에서 `node scripts/seminar-signup/check-ready.mjs cupsnballs`로 실행합니다. 행사 생략 또는 `daebeongae`는 기존 대번개를 검사합니다. 알 수 없는 행사 ID는 네트워크 요청 전에 거절합니다. 이 개발 작업에서는 실제 명단에 대한 연결 검사를 실행하지 않습니다.

### 운영자 확정 답변의 설정 (2026-11-27)

Q46·Q52·Q54에 대한 운영자의 후속 확정 답변을 기본값으로 반영했습니다. 만 14세 이상 확인을 유지하며, 참가자 분석을 위해 생년월일·성별·유입 경로·신청 이유를 모두 필수로 받습니다. 촬영은 필수 ‘네’ 하나로 현장 촬영과 홍보 활용을 함께 확인합니다. 다음 서버 환경변수를 변경하면 조회 응답과 제출 검증에 반영됩니다. 기존 대번개의 질문·고지와 저장된 동의 이력은 바꾸지 않습니다.

| 환경변수 | 기본값 | 변경 방법 |
| --- | --- | --- |
| `CUPSNBALLS_MINIMUM_AGE` | 만 14세 이상 확인 | `0`이면 확인을 끕니다. 그 외 값은 14세 기준입니다. |

기본 설정에서는 만 14세 미만 신청을 온라인으로 받지 않으며 보호자 문의를 안내합니다. 기본 설정은 촬영·홍보 활용 통합 동의가 필수입니다. `split`으로 바꾼 경우에만 홍보 활용 동의 없이 신청할 수 있습니다. 고지·설정 변경 후에는 서버와 Apps Script의 동의 버전을 맞추고, 이전 고지를 보고 열어 둔 화면의 신규 제출이 거절되는지 시험하세요. 설정 변경으로 이미 접수된 영수증과 동의 기록을 덮어쓰지 않습니다.

Q54의 강사는 운영자의 후속 답변에 따라 문준영으로 확정했습니다. 판매·접수 주체는 운영자이며 신청·입금을 직접 받고, 대관비·일회용품 등 비용을 공제한 뒤 문준영 강사에게 지급합니다. 신청 화면의 판매자 안내에도 운영자가 신청·입금을 받고 비용을 공제한 뒤 강사에게 지급하는 전체 흐름과 참가자 구성 정보의 전달 범위를 명시합니다. 운영자는 문준영 강사에게 수업 난이도 조절을 위한 성별 비율·연령대 등 구성 정보만 전달하고, 참가자 이름·전화번호와 원본 명단은 공유하지 않습니다. 개인정보 안내와 판매자 안내는 존댓말을 사용합니다. 삭제 요청은 운영자가 신청 후 보내는 카카오톡 메시지에 답장하는 경로이며, 컵앤볼 탭 또는 해당 신청 행과 내려받은 사본은 행사 종료 후 30일 이내 삭제합니다. 환불은 행사 7일 전까지 100%, 6-3일 전 70%, 2-1일 전 50%, 당일 불가로 안내하고 운영자가 날짜와 원 입금을 확인합니다.

`SEMINAR_SHEET_ID`, `CUPSNBALLS_SHEET_ID`, `CONTACT_SHEET_ID`에는 같은 비공개 파일 ID를 입력합니다. Netlify의 `SEMINAR_SHEETS_WEBAPP_URL`, `CUPSNBALLS_SHEETS_WEBAPP_URL`, `CONTACT_SHEETS_WEBAPP_URL`에는 한 웹 앱 배포의 같은 `/exec` 주소를 입력하세요. 각 양식은 서로 다른 서명 키를 사용합니다. 컵앤볼에는 `CUPSNBALLS_SHEETS_SIGNING_SECRET`과 `CUPSNBALLS_CONSENT_VERSION`을 설정하세요. 회원 연결을 추가하기 전 기본값은 `2026-11-27-c9d805338739`, 추가 후 이 커밋의 기본 설정 후보는 `2026-11-27-e35315392865`입니다. 실제 배포에 지정할 동의 버전은 현재 컵앤볼 공개 조회 응답의 `consentVersion`과 정확히 맞춥니다. 이 값은 `JSON.stringify({formConfig,privacyNotice,photoNotice})`의 SHA-256 앞 12자리와 `2026-11-27-` 접두어를 결합해 계산하므로 위 스위치를 변경할 때마다 다시 대조해야 합니다. 촬영 안내 버전도 같은 값을 사용합니다. 속성의 파일 ID·서명 키를 인수 문서에 복사하지 마세요.


개시 전 전용 서버 환경에서 현재 버전만 확인하려면 아래 명령을 실행하세요. 계좌·키·파일 ID는 출력하지 않습니다.

```sh
node --input-type=module -e "import {getEvent} from './netlify/functions/_lib/seminar-events.mjs'; console.log(getEvent('cupsnballs').consentVersion)"
```

준비 검사는 컵앤볼 요청에 이 버전을 서명해 보냅니다. 스크립트 속성의 버전이 누락되거나 다르면 준비 성공을 반환하지 않습니다. 이번 전환에서는 아래 「선택 동의 명단 전환과 회원 신청 개시」 순서로 기존 비회원 접수를 유지하면서 버전을 겹쳐 운영하고 `node scripts/seminar-signup/check-ready.mjs cupsnballs`의 성공을 확인하세요. 이전 접수의 재전송은 최초 영수증을 보존합니다.

공개 컵앤볼 조회의 `availabilityState`는 `scheduled`(개시 전), `ended`(마감 후), `unavailable`(현재 접수 설정 미준비 또는 비활성), `open`(접수 가능)으로 구분합니다. 컵앤볼 명단은 60명을 넘겨도 자동 마감하지 않으며, 물리 행과 입금 검증·색상·필터·입금 열 수정 가능 범위를 잠금 안에서 확장합니다.

## 대번개 연령 확인·고지 개정 (2026-11-30)

신규 대번개 신청은 만 14세 이상 확인과 생년월일의 한국 날짜 기준 만 나이를 모두 검사합니다. 만 14세 미만은 보호자가 문의하여 동의 절차를 완료하기 전에 온라인 신청할 수 없습니다. 연령 확인 도입 당시 두 고지 버전은 모두 `2026-11-30-v2`였습니다. 회원 연결 도입 시 개인정보 고지는 `2026-11-30-v3`, 촬영 고지는 `2026-11-30-v2`로 서버와 Apps Script를 맞춥니다. 이후 버전을 올려도 연령 검사는 유지합니다.

## 회원·비회원 문의 보관 및 알림 (2026-11-28 시행)

문의는 비공개 Google 스프레드시트의 `문의` 탭에 보관합니다. 행사 신청과 같은 파일·프로젝트·웹 앱 배포를 사용합니다. 일반 액세스는 제한됨으로 두고 운영자만 원문을 확인합니다. 관리자 페이지 조회는 후속 작업이며 현재 제공하지 않습니다.

공용 Apps Script 프로젝트에서 스크립트 속성 `CONTACT_SHEET_ID`, `CONTACT_SHEETS_SIGNING_SECRET`을 설정합니다. `setupInquirySheet()`는 빈 탭에 문의 번호, 접수 시각, 회원 구분, 답장 연락처, 문의 내용, 재시도 키, 요청 지문, 알림 상태, 답변 완료일 머리글을 준비합니다. 기존 응답 행이나 다른 머리글이 있으면 변경하지 않습니다. 답변 완료일을 제외한 원본 열은 보호합니다. 파일·스크립트 설정과 실제 배포는 이번 작업에서 실행하지 않았습니다.

서버에는 다음 이름을 설정합니다. 값은 공개 코드·운영 인수 문서에 복사하지 않습니다. 서명 키와 HMAC 키는 각각 32바이트 이상이며 서로 달라야 합니다.

```text
CONTACT_SHEETS_WEBAPP_URL
CONTACT_SHEETS_SIGNING_SECRET
CONTACT_HMAC_SECRET
DISCORD_CONTACT_WEBHOOK_URL
```

`GET /api/contact`는 설정, HMAC 서명한 `inquiry_readiness` 요청에 대한 HTTPS 응답의 머리글 상태, 만료된 IP 제한 항목을 정리한 뒤의 저장 여유가 모두 맞을 때만 `open: true`를 반환합니다. 응답 자체에 별도 서명은 없습니다. 신규 POST는 필수 설정이 없으면 닫힙니다. 문의 저장은 별도 서명 action `inquiry_submit`, 읽기 전용 결과 확인은 `inquiry_status`, 알림 확인 기록은 `inquiry_alert`로 분리합니다. 원문과 답장 연락처는 URL에 넣지 않습니다. 회원 구분은 서버에서 검증한 계정으로 기록하며 브라우저가 보낸 닉네임을 믿지 않습니다.

신청자의 브라우저는 전송 전에 한 문의의 UUID 재시도 키, 원래 본문·답장 연락처, 회원 ID 또는 비회원 구분을 해당 탭의 세션 저장소에 기록합니다. 기록을 보존할 수 없으면 POST를 보내지 않습니다. 초안은 별도 세션 저장소 항목에 기록합니다. 접수 확인 때 두 항목을 지우며 탭을 닫으면 세션 저장소가 종료됩니다. 응답이 유실되거나 503이 반환돼도 새로고침 후 같은 키를 복원합니다. 신규 접수가 닫혀도 폼 밖의 결과 확인 버튼은 유지합니다.

결과 확인은 `POST /api/contact`의 `action: status`로 원래 키와 본문·답장처를 보내고, 서버가 검증한 회원 ID 또는 비회원 구분을 HMAC 요청 지문에 포함합니다. 닉네임 변경은 같은 회원의 결과 조회를 막지 않습니다. 다른 계정이나 바뀐 원문으로는 조회할 수 없습니다. 상태 조회는 문의 행을 추가하거나 알림을 발송하지 않습니다. `accepted`이면 최초 접수번호를 확인하고 브라우저 임시 기록을 삭제합니다. `unknown`은 미접수 확정이나 자동 재접수로 해석하지 않습니다. 사용자가 명시적으로 같은 문의 다시 보내기를 선택할 때만 최초 키와 내용을 재사용합니다. 접수 종료 상태의 `unknown`은 기록을 유지하고 새 접수를 막습니다. 저장소 설정 자체가 없으면 조회도 닫히며 임시 기록은 유지합니다. 계정 동의 취소 시 전송 중단을 안내하고, 이미 전송한 요청은 계정을 바꾸어도 삭제하지 않습니다. 같은 키로 내용을 바꾸면 충돌로 거절합니다. 원문 저장과 알림 발송 대상 지정은 시트 잠금 안에서 한 번만 처리합니다. 봇용 숨김 칸, 링크 수·길이 제한, Netlify의 도메인·IP별 60초 3회 제한과 시트의 IP 대조값별 60초 3회 제한을 함께 적용합니다. 저장된 문의의 재조회는 시트 제한 횟수를 추가로 쓰지 않습니다. 외부 도메인·IP 제한과 함수의 짧은 요청 제한은 조회에도 적용됩니다. 시트 준비 확인과 신규 접수는 잠금 안에서 60초 유효기간이 지난 `inquiry_rate_` 속성을 먼저 삭제한 뒤 용량을 판정합니다. 문의 행·유효한 제한 항목·다른 스크립트 속성은 지우지 않습니다. 저장소가 가득 차도 유효기간 이후 준비 확인 또는 신규 요청에서 자동 회복하며, 주기 작업을 설치하지 않습니다.

Discord에는 `새 문의가 접수되었습니다`와 접수 시각만 전달합니다. 회원 ID·닉네임·답장 연락처·문의 번호·본문은 전달하지 않으며 멘션을 허용하지 않습니다. `wait=true` 응답에 실제 메시지 번호가 있을 때만 시트 알림 상태를 `확인됨`으로 기록합니다. 저장 성공은 문의 접수를 뜻하며 Discord 전달 완료를 보장하지 않습니다.

알림 응답이나 저장 응답이 유실되면 중복 알림 방지를 위해 자동 재발송하지 않으며 해당 행을 `미확인`으로 남깁니다. 운영자는 문의 탭의 미확인 행을 직접 확인합니다. 알림이 오지 않았다는 이유로 신청자에게 재작성하도록 요청하지 않습니다. 수동 재알림은 Discord 기록을 먼저 대조한 후 판단합니다.

운영자는 답변을 마친 날을 `답변 완료일`에 기록하고, 그날부터 1년이 지나면 해당 문의 원문·회원 구분·답장 연락처·시스템 기록과 내려받은 사본을 삭제합니다. 답변 완료일이 비어 있으면 처리 중인지 점검합니다. 행사 명단 30일 삭제 절차를 문의 탭에 실행하지 않습니다. 삭제·주기 작업은 자동으로 설치하지 않았으며 운영자가 직접 관리합니다.

## 선택 동의 명단 전환과 회원 신청 개시

1. 현재 배포와 웹 앱 버전, 각 행사의 고지 버전, 명단 행 수와 필터·보호·입금 표시·발급 카운터를 제한된 운영 환경에 기록하세요. 운영 파일의 접근 권한을 유지하는 백업을 마련하고, 별도 시험 파일·키와 합성 명단으로 전환을 연습하세요.
2. Apps Script 편집기의 서비스에서 **Google Sheets API v4**를 추가하세요. 표준 Cloud 프로젝트라면 해당 프로젝트에서도 Sheets API를 사용 설정하세요. 기존 웹 앱의 배포 관리에서 새 버전을 배포해 URL과 실행 계정을 유지합니다. 기존 요청이 끝날 때까지 기다린 뒤 두 행사와 문의 연결을 점검하세요. 편집기 저장만으로 배포가 갱신되지는 않습니다.
3. 신규 빈 탭은 준비 함수를 사용합니다. 기존 컵앤볼 31열은 위의 표시 접수번호 전환을 먼저 마치세요. 32열 컵앤볼에는 `migrateCupsnballsMemberSheet()`, 29열 대번개에는 `migrateDaebeongaeMemberSheet()`를 실행하세요. 함수는 접수와 같은 잠금 안에서 데이터·서식·필터를 점검하고 Sheets API 요청 한 묶음으로 두 열을 삽입합니다. 동일 함수를 다시 실행해 최종 데이터와 서식을 점검하세요. 미지원 범위, 직접 입력된 수식, 보호 설정 또는 필터 수식 오류는 변경 전에 해결합니다. 실행 결과를 받지 못했다면 같은 함수를 다시 실행해 확인하세요.
4. 컵앤볼은 AE 표시 접수번호, AF 신청 구분, AG 사이트 회원 식별자, AH 입금입니다. 대번개는 AC 신청 구분, AD 사이트 회원 식별자, AE 입금입니다. 0·1 입력 검사와 행 전체 입금 표시, 필터 조건, 입금 열 편집 예외를 백업과 대조하세요. 처리 도중 들어온 신청은 원래 재시도 키로 대조하세요. 10초 잠금 대기를 넘기면 회원 공개를 미루고 비회원 접수를 유지합니다.
5. 컵앤볼의 기존 `CUPSNBALLS_CONSENT_VERSION`을 유지합니다. 실제 운영 설정으로 생성한 새 고지 해시를 `CUPSNBALLS_NEXT_CONSENT_VERSION`과 `CUPSNBALLS_LINKAGE_CONSENT_VERSION` 양쪽에 입력하세요. 회원 연결은 승인된 해당 고지에서만 가능합니다. 대번개는 개인정보 v3, 촬영 v2이며, 구 버전 요청이 남은 동안 기존 개인정보 v2로 비회원 접수가 가능합니다. 회원 신청 공개 전 비공개 환경에서 두 행사의 `check-ready.mjs` 검사로 최종 열과 고지 버전 일치를 확인하세요.
6. 정책·양식·함수를 함께 공개한 뒤 기존 호출이 끝나면 컵앤볼 활성 버전을 새 해시로 교체하고 NEXT 속성을 삭제하세요. LINKAGE 속성은 승인된 해시로 유지합니다. 대번개는 `SEMINAR_ACCEPT_PREVIOUS_NOTICE=false`로 이전 고지를 종료합니다. 장애 시 회원 선택만 비활성화하고 같은 명단·고지·호환 서버로 비회원 접수를 유지하세요. 데이터 무결성을 확인할 수 없으면 해당 행사 쓰기를 멈추고 재시도 키로 대조합니다. 운영 명단 위에 예전 백업을 덮어쓰지 마세요.
7. 행사 종료 후 30일 이내(대번개 2027년 2월 9일)에 회원 식별자와 선택 동의 기록을 포함하는 명단 행·서버 기록 JSON·시험 및 운영 사본·CSV·백업을 함께 삭제하세요. 강사에게는 기존 참가자 구성 집계만 제공합니다.

두 행사의 신규 요청 한도는 행사별 같은 IP의 해시당 600초에 180건입니다. 동일 연락처는 해당 행사에서 한 시간에 세 건까지 접수됩니다. 완료된 재시도는 새 한도를 쓰지 않습니다. 대번개 60석과 컵앤볼의 분당 표시번호 한도는 별도로 적용됩니다. 이전 IP 한도 키는 만료 후 정리되며, 새 키는 행사별로 시작합니다. 개시 10분 이상 전에 전환하고 격리 환경에서 동시 부하와 잠금 대기 시간을 측정하세요.
